# run --json Event Stream in TofuPilot
URL: /docs/cli/json-events

Learn how to drive tofupilot run programmatically with the NDJSON event stream and stdin commands for agents and automation.

***

title: "run --json Event Stream in TofuPilot"
description: "Learn how to drive tofupilot run programmatically with the NDJSON event stream and stdin commands for agents and automation."
sidebarTitleCode: run --json
----------------------------

`tofupilot run --json` emits a newline-delimited JSON (NDJSON) event stream on stdout. Each line is one event object with a `type` field and a `seq` counter. The stream is the integration surface for agents, MES bridges, and CI automation: everything the operator UI shows is also on the wire.

```bash title="stream a run as NDJSON"
tofupilot run ./procedures/pcb-fvt --json
```

```json title="example stream (abbreviated)"
{"type":"run_started","procedure_id":"pcb-fvt","protocol_version":"1.0","seq":0}
{"type":"plan","phases":[{"key":"flash","name":"Flash firmware"}],"seq":1}
{"type":"phase_started","phase_key":"flash","attempt":1,"slot_id":"default","started_at":"2026-06-10T08:00:00Z","seq":2}
{"type":"phase_finished","phase_key":"flash","outcome":"PASS","duration_ms":1240,"seq":3}
{"type":"run_finished","outcome":"PASS","exit_code":0,"seq":4}
```

## Protocol guarantees

* **Versioned**: `run_started` carries `protocol_version` (currently `1.0`). New optional fields can appear without a version bump; ignore unknown fields. Removals and renames bump the version.
* **Ordering**: `seq` starts at 0 and increments by 1 per line. It is the only reliable ordering primitive; timestamps are advisory for display.
* **Terminal invariant**: `run_finished` is always the last event. If the Python subprocess died, `run_crashed` immediately precedes it. Stop sending stdin commands after `run_finished`.
* **stderr stays human**: progress notes, warnings, and errors go to stderr; stdout carries only event lines.

## Event reference

| `type`                                                                                     | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `run_started`                                                                              | First event. Carries `procedure_id` and `protocol_version`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `plan`                                                                                     | Ordered phase list as `{key, name}` tuples.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `phase_started`                                                                            | Phase entered execution: `phase_key`, `attempt`, `slot_id`, `started_at`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `phase_finished`                                                                           | Outcome, timestamps, `duration_ms`, recorded measurements, optional `error`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `phase_skipped`                                                                            | Phase never ran (upstream failure or `on_first_failure: stop`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `phase_log`                                                                                | Live log line from a running phase.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `ui_request`                                                                               | Operator prompt with the component specs. Reply with `ui_response`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `ui_auto_continue`                                                                         | Prompt auto-resolved (display-only components or pre-baked `--ui-values`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `ui_update`                                                                                | A phase changed an open prompt: `action` is `set_value` (`data: {id, value}`, from `ui.<key> = value`) or `set_properties` (`data: {id, properties}`, from `ui.set`). Fold `data` into the `ui_request` with that `request_id`. `data.properties` carries only the fields a `ui_request` component shows you (`label`, `description`, `placeholder`, `options` as value and label, `min`, `max`, `step`), `null` for a cleared one. Options set at run time are the list your `ui_response` is checked against. `request_id` is absent on a display-only prompt, which has nothing to answer, and once the prompt it belonged to has been answered (a phase may keep updating its screen after your `ui_response`). |
| `ui_timeout`                                                                               | Prompt expired without a response (`--ui-timeout`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `ui_cancelled`                                                                             | The prompt's phase was interrupted (a stop, or OpenHTF's own phase timeout) before anyone answered. The request is withdrawn, a late `ui_response` to it is refused as unknown. OpenHTF only.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `ui_error`                                                                                 | A stdin command was rejected; `reason` enumerates the cause.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `identify_request`                                                                         | Unit identification prompt (serial number, part number).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `identify_resolved`                                                                        | Identification accepted.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `identify_timeout`                                                                         | Identification expired (`--ui-timeout`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `plug_status`                                                                              | Plug lifecycle transition (initializing, active, error). Carries `scope` (`slot`, `execution`, or `station`; legacy emitters said `each`/`all`) and `slot_id` (`null` for execution- and station-scope plugs, which are shared across slots).                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `plug_log`                                                                                 | Live log line from a plug's Python service.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `measurement_recorded`                                                                     | Live measurement write (streaming preview; full records arrive on `phase_finished`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `attachment_added`                                                                         | Phase attached a file.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `state_snapshot`                                                                           | Reply to `get_state`: `run_status`, phase history, any in-flight `active_ui_request`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `run_upload_queued`                                                                        | Run persisted to the local queue for deferred upload.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `run_upload_started` / `run_upload_succeeded` / `run_upload_failed` / `run_upload_dropped` | Upload lifecycle for queued runs. `run_upload_succeeded` carries the final `run_id` and `dashboard_url`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `internal_warning`                                                                         | Non-fatal CLI anomaly, for example payload truncation.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `run_crashed`                                                                              | Subprocess died before completing; immediately precedes `run_finished`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `run_finished`                                                                             | Last event: `outcome` and `exit_code`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

Large payloads are capped: `measurement_recorded.value` truncates above 1 MB (replaced by `{"truncated": true, "original_size_bytes": N}` plus an `internal_warning`).

## Stdin commands

The CLI reads NDJSON commands on stdin while the run is active:

| Command       | Purpose                                                                                                                                                                                                                                                                                                                      |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ui_response` | Answer a `ui_request` by `request_id` with component values. Answers are checked by the same validator as the kiosk (required fields, bounds, `step`, `pattern`, selections against the current option list) and refused with `ui_error` (`reason: "invalid_value"`, the field and the message) while the prompt stays open. |
| `abort_run`   | Stop the run. Rejected with `ui_error` (`reason: "invalid_state"`) before `run_started` or after `run_finished`.                                                                                                                                                                                                             |
| `get_state`   | Request a `state_snapshot` to recover after reconnecting mid-run.                                                                                                                                                                                                                                                            |

```json title="answer a prompt"
{"type":"ui_response","request_id":"<id from ui_request>","values":{"operator_note":"ok"}}
```

## Headless runs

Prompts block the stream until answered. For unattended runs:

* Set `unit.auto_identify: true` with `serial_number.default_value` and `part_number.default_value` in the procedure `.yaml` file, or give every unit field a `default_value` with `locked: true`, so the identify prompt resolves itself.
* Pass `--ui-values <file>` to pre-bake answers for UI phases; an empty map `{}` resolves display-only and acknowledgement prompts.
* Pass `--ui-timeout <seconds>` so an unanswerable prompt fails the phase instead of hanging forever.

```bash title="unattended CI run"
tofupilot run ./procedures/pcb-fvt --json --ui-values ui.json --ui-timeout 300
```
